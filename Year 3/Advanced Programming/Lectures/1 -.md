
Why concurrent programming?

- Performance fain from multiprocessing hardware
- Increased application throughput
- Increased application responsiveness
- More appropriate structure
	- For programs which interact with the encitonment, control muliple activities and handle multiple events. 


Parallel vs Concurrent Programming

Parallel
- Do as many concurrent actions, as quickly as possible

Concurrent
- Happy if we do them correctly


Parallel Slowdown
- As processors increase, speedup decreases and may even become negative
- Coordination has a cost
- Brooks's Law "Adding manpower to a late software project makes it later"
